GUI tour

The window you'll be working in.

BIDS Manager opens on the Home tab, where you create or open a dataset project, then gives you two working views: the Converter (raw → BIDS) and the Editor (read, fix, validate). Pick a tab below, then hover or click a numbered marker to learn what each part of the window does. To watch these features in action, head to the GUI tour.

View switcher

The three top-level tabs that run the whole app: Home (this project screen), Converter (raw → BIDS), and Editor (read, fix, validate). The Converter and Editor stay disabled until a project is open, which is why the workflow always starts here.
Create a new dataset

Type a name and pick a location, and BIDS Manager scaffolds a fresh BIDS dataset: dataset_description.json, a README, and a .bidsignore, plus the project bundle that records your work. The folder name becomes the dataset slug used throughout. This is the usual starting point.
Open an existing dataset

Continue a BIDS Manager project exactly where you left off, or adopt a dataset that was created elsewhere. An adopted dataset is opened read-only and is never overwritten, so you can browse, view, and validate it with no risk of changing the files.
Recent projects

Every project you have created or opened, each with its full path. Double-click one to reopen it; right-click to remove it from the list or delete it from disk. This list, plus the saved project bundle, is what makes curation resumable across sessions.
Getting started

Shortcuts to the documentation, this tutorial, and the source code, plus the sample datasets that ship as links: MRI, EEG, MEG and an advanced MRI set. The documentation site carries two more, PET and a multimodal set, on its Tutorials pages.
Settings + theme

The gear opens Settings, seven tabs: BIDS version, Display, System, Scan, Scan rules, Convert + post-convert, and Validation. The first decides which version of the standard this session works to, and reaches everything downstream. The sun / moon button beside it toggles the theme live. Both sit at the far right of the header on every screen.

View switcher

The Home / Converter / Editor tabs. You're in the Converter, where the raw folder is turned into a curated BIDS dataset.
Scan

The Scan… button walks the raw input folder and builds the inventory; the Scan table dropdown beside it names the current scan. Re-scanning saves a new versioned snapshot inside the project instead of overwriting the previous one, so earlier scans stay recoverable.
Project switcher + Undo / Redo

The dropdown shows the active dataset and moves between open projects (or back to Home). Undo and Redo in the toolbar below step through your curation edits; because every change is recorded in the project bundle, nothing is ever lost.
Status chips + Re-validate

Four chips summarise the inventory, valid, warnings, error, and skipped, and update live as a scan runs. Three are clickable to list the rows behind them. Re-validate re-checks every row's entities after you edit them.
Run conversion

Writes the curated rows to the project's BIDS root, running the right backend per modality. It stays disabled until a scan has finished, and flips to Cancel while a conversion is in progress.
Settings + theme

The gear opens Settings, seven tabs: BIDS version, Display, System, Scan, Scan rules, Convert + post-convert, and Validation. That is where you set which version of the standard to work to, the worker counts, your own scan rules, and the chain that runs after every conversion. The sun / moon button toggles the theme live.
PathBars

Raw input is the folder you scan. BIDS output is locked to the open project, so it cannot be pointed at the wrong place. The glyph at the left of each bar flips from a circle to a check when the path is valid.
Raw & output trees

The top tree browses the raw input folder exactly as it sits on disk (a read-only navigator). The bottom tree previews the future BIDS layout the conversion will write, including dataset_description.json, participants.tsv, and each subject folder.
Filter / structure

Every series grouped by schema entity (subject / session / datatype) with tri-state checkboxes. Filter by entity to focus the Inspection table on a subset, or untick a whole group to exclude those rows from the next conversion.
Inspection table

The centre of gravity: one editable row per recording, with the predicted basename, datatype, task, run and the classifier's confidence. Rows are tinted by status (keep, skip, non-image, warning), and a predicted basename turns red when another row wants the same filename, which blocks the conversion until you resolve it. Any cell can be edited by clicking it.
Curation actions

The buttons beneath the table: Dataset metadata opens the dataset-wide editor (including the EEG / MEG enrichment: reference, ground, filters, device, event labels); Manage columns shows, hides, and reorders columns; Bulk edit sets an entity on many selected rows at once.
Properties panel

A schema-aware editor for the selected row. It shows only the entities valid for that row's datatype + suffix, marks required fields with a red asterisk, and updates the predicted path as you type. EEG / MEG rows also expose minimal metadata and per-row device overrides.
BIDS preview & log dock

The bottom dock with tabs: Log (engine output during scan and conversion), BIDS preview (the exact filesystem layout that will be written), and Statistics.

View switcher

You are in the Editor: read the converted dataset, edit sidecars and tables, look at images and recordings, and run validation. The other two tabs are the Home screen and the Converter.
Validate at three scopes

Validate file, folder and dataset run the same checks over different amounts of the tree. Dataset also checks the things no single file is responsible for, such as whether the files listed in a scans table are the ones actually present.
Deep checks

Off by default. When on, validation additionally opens NIfTI image headers and reads file contents, which catches a truncated or corrupt image that every name-based check would pass. Slower on large trees, so it is a per-run choice rather than a setting.
Severity chips

A live count of the whole dataset: valid files, warnings, errors. Click one to open the list of files carrying that severity and jump straight to any of them.
Undo and redo

Editing is undoable, and it covers both sidecar fields and table cells, so you can try a change and step back from it.
The dataset path

Which dataset is open. change… opens another. The Editor can open any BIDS dataset, including one produced by something else.
BIDS tree

The converted layout, with a coloured dot on every file: green clean, amber a warning, red an error. A folder carries the worst dot beneath it, so a red dot at the top can be followed down to the file responsible without opening anything.
Viewer, routed by file type

Whatever you select opens in the editor built for it: this schema-aware form for JSON sidecars, an editable table for TSVs, the image viewer for NIfTI, and the signal viewer for EEG, MEG and iEEG recordings. BIDS view lists the fields the standard declares; Tree view shows the raw keys and values.
Revert and Save

Edits are written back to the file on Save. Revert drops them and reloads from disk.
Validation pane

Three scopes at once: findings about the dataset, about the folder you are in, and about the selected file, each with its own count. Every finding carries the rule in the BIDS schema it came from.
Highlight in editor

Tints every field or column on this file that a finding refers to, so you can see them all at once rather than one at a time.
Fix

Takes you to the exact field or table column the finding is about. On a TODO placeholder the button reads Set a real value instead.
